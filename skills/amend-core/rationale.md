# Rationale

Why the core's rules and skills are shaped as they are. An entry gets in only where an editor without it would plausibly cut or reverse the rule it explains. It changes in the same edit as its rule, and goes when its rule goes.

## Bindings

Where a rule touches a domain, the core keeps its domain-free part and each knowledge base states the binding in the file every session reads. A binding stays a noun because that file loads at the start of every session, so a step or a rule placed there is read long before the writing it governs.

## Cold Reader

The silhouette of a rule, shaped like the one case its author met, survives the ban on examples, so an edit to a rubric needs a cold reader as much as a document does.

## No Examples

The instances a writer lists are the ones its session happened to meet, so the list is incomplete the day it is written. Writers copy what they read, and a later writer copies every trait an instance carries, not only the one it was chosen for. A specimen is the one-entry case: where it is the only instance in view, it teaches its accidents.

Where no specimen is in view, the documents already written teach instead, so banning examples leaves no writer without a voice to copy.

## No Memories

A memory lives on one machine, outside review, and drifts from a rubric that changes only through discussion.

## Fix by Subtraction

A clause added after a failure takes the shape of that failure and no other. A rubric's reader never had the session that prompted the clause, so a clause aimed at one session's mistake reads to every later writer as someone else's argument.

## Just in Time

A read early in a long session has decayed by the time the writing comes, so each writer reads its rules at its own step.

## The rubric's own prose

The rubric is meant to be the last document a writer reads before writing, so its prose teaches faster than its rules do. That is why a change to it is held to its tests harder than any document it governs.

## What is shared

`checkin` carries the commit rules as a skill rather than as a section of a rubric file. A harness's own commit guidance wins wherever no commit rule is in view, and a skill's description is the only loader that works where no orchestrator calls it.

The messaging rules are a file of their own because they compress, and compressing a home is damage. `MESSAGING.md`'s One Claim and Named Things stay with them: fusion is what a writer does when squeezed into a title or a reply.

`improve-code` is shared although it invokes `audit-comments` and runs tests, because the audit is the core's and the tests are the repository's, and it leaves what remains to the knowledge base's writer of code and recording step without sequencing either.

## export-thread

The agent reads neither the transcript nor the export because a model that reads and rewrites a session pays for its whole length, where the script's one command costs the same however long the session ran.

## improve-code

Reuse, simplification, efficiency and altitude each have an agent of their own, because an agent holding all four gives each less attention, and that attention is where the cleanup comes from. The correctness angles share one agent, because all three read the same lines and the same callers, and one context sees how their findings combine.

The deletion reviewer compares against the code at the scope's start, because what a mechanism adds over the code it replaced shows nowhere in the diff, and a reviewer held to the diff improves a mechanism rather than asking whether it should exist.

A reviewer returns what it half believes because verifying is the running session's step, and a reviewer that filters its own candidates is the commonest miss.

The comment audit runs after the apply rather than before it, because an apply phase that followed the audit would land the only comments no fresh reader ever sees.

## slack-log

The markdown is redrawn from the store rather than appended to, because replies keep arriving under older parents, and an appended log files a reply away from its thread.

Curation keeps or drops whole threads, because a thread trimmed to its relevant replies is a paraphrase of the conversation.
